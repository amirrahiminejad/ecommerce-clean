# پروژه آموزشی فروش اینترنتی با Clean Architecture

این پروژه یک نمونه‌ی کوچک و آموزشی از فروش اینترنتی است که با زبان Java و فریم‌ورک Spring Boot نوشته شده است. هدف اصلی، آموزش اصول Clean Architecture و تقسیم مسئولیت‌ها بین لایه‌هاست.

## معماری پروژه

ساختار پروژه به صورت لایه‌ای طراحی شده است:

- `domain` : مدل‌های اصلی کسب‌وکار و قراردادهای Repository
- `application` : سرویس‌های کسب‌وکار و DTOها
- `infrastructure` : پیاده‌سازی JPA و وابستگی‌های فنی
- `interfaces` : کنترلرهای REST API

## Entity‌های اصلی

این پروژه تنها 4 Entity اصلی دارد:

1. `Customer` : مشتری
2. `Product` : کالا/محصول
3. `Order` : سفارش
4. `OrderItem` : آیتم سفارش

## امکانات پروژه

- نمایش محصولات
- نمایش مشتریان
- ایجاد سفارش برای یک مشتری
- ثبت آیتم‌های سفارش
- کاهش موجودی محصول بعد از ثبت سفارش
- محاسبه‌ی مجموع سفارش
- استفاده از دیتابیس در حافظه با H2
- API REST برای تعامل با برنامه

## اجرای پروژه

ابتدا وابستگی‌ها نصب شوند:

```bash
mvn clean install
```

سپس برنامه را اجرا کنید:

```bash
mvn spring-boot:run
```

## آدرس‌های API

- لیست محصولات: `GET http://localhost:8080/api/products`
- جزییات محصول: `GET http://localhost:8080/api/products/{id}`
- لیست مشتریان: `GET http://localhost:8080/api/customers`
- ثبت سفارش: `POST http://localhost:8080/api/orders`
- کنسول H2: `http://localhost:8080/h2-console`

## مثال JSON برای ثبت سفارش

```json
{
  "customerId": 1,
  "items": [
    { "productId": 1, "quantity": 2 },
    { "productId": 2, "quantity": 1 }
  ]
}
```

## اصول Clean Architecture در این پروژه

- `domain` مستقل از Spring و دیتابیس است.
- `application` منطق کسب‌وکار را اجرا می‌کند.
- `infrastructure` پیاده‌سازی‌های فنی مانند JPA را انجام می‌دهد.
- `interfaces` تنها ورودی و خروجی HTTP را مدیریت می‌کند.
- هر لایه فقط به لایه‌ی پایین‌تر وابسته است و از لایه‌های بالاتر استفاده نمی‌کند.

## نکات آموزشی

این پروژه برای یادگیری طراحی نرم‌افزار و Clean Architecture مناسب است. اگر بخواهید، در مراحل بعدی می‌توانید این قابلیت‌ها را اضافه کنید:

- مدیریت وضعیت سفارش (`PAID`, `CANCELLED`)
- اعمال کد تخفیف
- پرداخت آنلاین
- ثبت نام و احراز هویت
- تست‌های واحد و تست‌های یکپارچه
- استفاده از PostgreSQL یا MySQL به‌جای H2
